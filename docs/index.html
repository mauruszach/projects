About the project & run locally ↓

This website is a static project showcase. The interactive apps and data pipelines run on your computer; no hosted refresh jobs or API-key forms run here.

Run the shared workspace locally

Use Git, Node.js 22 and Python 3.11 or newer. The commands below are for macOS/Linux or Windows through WSL. Run them in a terminal. Both apps start from the same repository.

git clone https://github.com/mauruszach/projects.git
cd projects
npm ci --prefix web
npm ci --prefix projects/polymarket/web
python3 -m venv projects/polymarket/.venv
projects/polymarket/.venv/bin/python -m pip install -r projects/polymarket/requirements-hosting.txt
node scripts/serve-site.mjs --dev

Open http://127.0.0.1:3000/ and choose a project. Keep the terminal open; press Ctrl+C to stop both apps. If port 3000 is occupied, use PORT=3008 node scripts/serve-site.mjs --dev and open port 3008 instead. Port 3107 is reserved for the local Polymarket app.

No API key is required to explore the sample graphs. Installing packages and refreshing Polymarket data requires internet access. Python analysis can take several minutes and substantial memory; use a machine with several GB of available RAM.

Alternative: run with Docker

With Docker and Docker Compose installed, from the cloned repository:

docker compose -f compose.site.yaml up --build -d

Open http://127.0.0.1:3008/. The image includes both apps and the Polymarket Python dependencies. Predictor uses demo events unless you separately connect its event API. Stop it with:

docker compose -f compose.site.yaml down

A 512 MB container was insufficient for this workload. Allocate several GB for local use; actual requirements depend on the data refresh.

PROJECT 01

Temporal Knowledge Graph Engine

GDELT event exports are transformed into actors, events and locations in Neo4j. A FastAPI service exposes the data. The Next.js interface lets you highlight relationships and inspect individual events without losing the surrounding graph.

Optional Claude calls propose actions for two actors and illustrative payoff matrices. The interface checks pure-strategy equilibria against those proposed numbers. A separate Python forecasting module explores graph-derived features and statistical baselines; it is not the same as the language-model scenario generator.

Explore the interface

Follow the shared setup above and open /predictor locally. It starts with labeled synthetic events if no backend is available. Use its “How it works” tab for the full methodology.

To generate a hypothetical matrix, enter your own Anthropic API key in the local interface. Model usage is billed to your account. The key stays in page memory and passes through your local server to Anthropic; reload or clear it to remove it from the page. Graph browsing needs no key.

Optional: reproduce the recorded-event pipeline

Install Docker for Neo4j. In a second terminal, from the repository root:

python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
cp .env.example .env
docker compose up -d neo4j
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000

The example configuration connects to local Neo4j on port 7688 using development credentials. Keep these local. Leave the Anthropic environment key empty unless running an operator enrichment script.

Once Neo4j is healthy, load a small, bounded historical interval from another terminal:

.venv/bin/python scripts/backfill_gdelt.py --start 2024-01-01T00:00 --end 2024-01-01T01:00

The frontend checks the local event API every 15 seconds. Loading an hour of data does not create an ongoing ingestion schedule. scripts/schedule_ingest.py processes one recent interval per invocation; automatic ingestion requires a separate scheduler.

Validation: run .venv/bin/pytest for the Python suite and cd web && node --test tests/*.test.mjs for frontend logic and mocked model calls. Neo4j integration tests require the database to be running.

CAMEO codes and Goldstein scores are noisy proxies for real-world escalation. Generated payoffs and events are assumptions, not measured outcomes or calibrated forecast probabilities.

PROJECT 02

Polymarket correlation graph and shock simulator

The pipeline pulls public market metadata from Gamma and price histories from the CLOB API. It screens markets for liquidity and history coverage, compares daily log-odds changes, and applies multiple-testing and robustness checks. The interface displays connections, historical charts and hypothetical shock responses.

Explore the interface

After shared setup, open /polymarket locally. The bundled historical snapshot appears first. Visiting the app starts or joins a fresh data job on your computer. Public data requests need no Polymarket trading key. Failed refreshes keep the previous snapshot labeled.

For a refresh failure, inspect the terminal output for Polymarket refresh failed. A new upstream dataset may differ from the bundled snapshot. This reproduces the workflow, not an identical set of live results.

Run the analysis without the interface

From the repository root, using the virtual environment created above:

projects/polymarket/.venv/bin/python projects/polymarket/scripts/find_correlated_markets.py --refresh --output-dir /tmp/polymarket-reproduction

Outputs include market_graph.json, market_graph_prices.json, and a correlation report in JSON and Markdown. The default screen examines up to 1,500 events with a 240-day lookback. Use --help to inspect its thresholds. Smaller --max-events values can reduce runtime but change the sample and may leave too few eligible markets.

Build verification: cd projects/polymarket/web && npm run build -- --webpack. With Node 22.13 or newer, run its mocked refresh tests using node --experimental-strip-types --test tests/*.test.mjs in that same directory.

Correlation does not establish causation. Shock propagation is conditional on historical relationships and model assumptions, not a trading recommendation or a guaranteed future price move.
